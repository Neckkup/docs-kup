# กฎการเขียน

## เนื้อหา

- **สภาพปัจจุบันเท่านั้น:** เขียนสิ่งที่โค้ดทำตอนนี้ เหตุผลว่าทำไมให้ลิงก์ไป spec, ADR หรือ plan ที่มีอยู่ ไม่เขียนแผนในอนาคต
- **ทุกข้อเท็จจริงมาจากการอ่านโค้ด:** ใส่ป้ายท้ายข้อ
  - `[โค้ด]` อ่านจาก source แล้ว
  - `[อนุมาน]` สรุปจากหลายจุด ยังไม่ได้ยืนยัน
  - `[วัดจริง]` ยืนยันจากการรันหรือ query จริง
  - ห้ามเดา ถ้าไม่แน่ใจให้ถามผู้ใช้ด้วย AskUserQuestion (หน้าต่างเด้ง) ก่อนเขียน `[อนุมาน]` ใช้ได้เฉพาะเรื่องที่ผู้ใช้ตอบว่าไม่รู้เหมือนกันและให้เขียนไว้แบบนั้น
- **ไม่คัดลอกรายการยาว:** endpoint, permission, ชื่อ event, คอลัมน์ทั้งหมด จะล้าหลังโค้ด ให้อธิบายรูปแบบ ยกตัวอย่าง 2–5 ตัว แล้วลิงก์ไปไฟล์ที่เป็นตัวจริง ตารางเล็กที่มีไม่กี่แถว (เช่น โมดูล 6 ตัว) ใส่ได้
- **ไม่ซ้ำกันระหว่างหน้า:** เรื่องเดียวอยู่หน้าเดียว หน้าอื่นลิงก์ไปหา เช่น ค่า env และขั้น deploy อยู่ใน ops/ci-cd เท่านั้น
- **แยกให้ชัดว่าส่วนไหนเป็นคู่มือ ส่วนไหนเป็นคำอธิบาย:** `backend/` และ `frontend/` เป็นคู่มือ (ทำอะไร พิมพ์คำสั่งอะไร) ส่วน `architecture/` เป็นคำอธิบาย (ทำงานอย่างไร)

## รูปแบบ

- ภาษาตามเอกสารเดิมของ repo ถ้าไม่มีเอกสารเดิมให้ถามผู้ใช้ด้วย AskUserQuestion ศัพท์เทคนิคคงภาษาอังกฤษ
- ประโยคสั้น ย่อหน้าไม่เกิน 3 ประโยค ไม่มีคำโปรย ไม่มีย่อหน้าสรุปท้าย
- บรรทัดแรกของไฟล์เป็น `# ชื่อ` บรรทัดถัดไป (ยกเว้น `README.md` ที่ root) เป็นลิงก์ย้อนกลับ `[← architecture](README.md)` หรือ `[← docs](../README.md)` แล้วตามด้วยประโยคนำ 1–2 ประโยคที่บอกว่าหน้านี้ตอบคำถามอะไร
- bullet ใช้รูป `- **หัวข้อ:** คำอธิบาย` และย่อยด้วยการเยื้อง ไม่เขียนเป็นย่อหน้ายาว
- ตารางใช้เมื่อเทียบหลายสิ่งในหลายมิติ ไม่ใช้ตารางกับข้อมูลคอลัมน์เดียว
- diagram ทุกรูปเขียนเป็น code block ` ```mermaid ` ในไฟล์ .md (GitHub/GitLab render ให้) ห้ามใช้ ASCII art, ไฟล์รูป หรือเครื่องมือวาดอื่น ยกเว้นแผนผังโฟลเดอร์ที่ใช้ tree ใน code block ธรรมดาได้
- mermaid ใช้เมื่อช่วยให้เข้าใจจริง หน้าละไม่เกิน 1–2 รูป (ยกเว้น `architecture/README.md` ที่มี container 1 รูป + data flow 3–4 รูป) รูปเล็ก ๆ: `graph` สำหรับ container/การพึ่งพา, `sequenceDiagram` สำหรับเส้นทาง request หรือ event, `erDiagram` 5–8 ตารางต่อโมดูล โดยใส่แค่ PK, FK และคอลัมน์สำคัญ 1–3 ตัว

## ลิงก์

- ลิงก์ไปโค้ดเป็น relative path จากไฟล์เอกสาร เช่น `[server.go](../../backend/internal/httpserver/server.go)`
- ชื่อโฟลเดอร์ที่มีวงเล็บ เช่น route group ของ Next.js `(app)` ต้องเข้ารหัสในลิงก์เป็น `%28app%29` ไม่งั้น markdown ตัดลิงก์ผิด
- ห้ามใช้ลิงก์แบบ `file:line` ไปยังโค้ดที่เปลี่ยนบ่อย ลิงก์ไปที่ไฟล์พอ
- path ในตารางหรือในข้อความที่ไม่ใช่ลิงก์ใส่ใน backtick
